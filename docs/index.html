Unobfuscated truth — no security theater

AssetShield does not make browser-delivered code impossible to inspect. It reduces exposure, protects asset access, and increases the cost of reverse engineering.

Capabilities

What a protected build looks like

Everything an asset request touches — the URL, the signature, the resolution, and the wire headers — is hardened by default. No database, no per-request scans.

01 · URL abstraction

Opaque, key-derived identifiers

Clients see a cipher-like id — never the real build filename. IDs are HMAC-derived from your application key: deterministic per build, non-sequential, and regenerated whenever the key rotates.

Blade  {!! AssetShield::script('resources/js/app.js') !!} before  /build/assets/app-A91Kx.js after  /assets/7f92a8c1
02 · Access control

Signed, expiring URLs

HMAC-SHA256 signatures with constant-time verification. Forged or expired links return HTTP 403.

/assets/7f92a8c1 ?expires=1790000000 &signature=ac42b8…
03 · Resolution

Registry-only lookup

IDs resolve exclusively through a generated registry. Traversal, absolute paths, and query-as-path are structurally impossible.

GET /assets?file=../../.env → 403
04 · Source discipline

Outside the web root

Resources, app, routes, vendor, node_modules, and .env never meet the public surface.

  • resources/ · app/ · routes/
  • vendor/ · storage/ · node_modules/
  • .env — never retrievable
05 · Wire behavior

Immutable caching, safe headers

Long-lived cache keys that CDNs can hold for a year — without breaking signature policy.

Cache-Control public, max-age=31536000, immutable X-Content-Type-Options: nosniff
06 · Build pipeline

Obfuscation, opt-in and vendor-safe

An adapter wraps javascript-obfuscator. Off by default; presets from light to aggressive; vendor chunks skip by default; CSS is never touched.

light balanced aggressive vendor: skipped dynamic imports: kept
07 · Maps

Source maps off

No .map files ship for protected assets — and enabling them triggers a loud warning.

get /assets/*.map → 404 denied
Architecture

One build. One registry. Two safe halves.

The Vite plugin produces the registry as a build artifact; the Laravel package consumes it, cached and OPcache-friendly. No database, no per-request filesystem scanning.

01

Vite build

The plugin runs only on vite build. Your chunking, hashing, and dynamic imports stay exactly as Vite made them.

  • manifest.json
  • optional JS obfuscation
  • CSS never obfuscated
02

Registry artifact

A single JSON file maps logical entries to compiled files to opaque IDs. Server-side only; the browser never sees the compiled paths.

  • logical → compiled → opaque
  • written by plugin or asset-shield:build
  • cached in production
03

Delivery layer

The controller verifies signatures, resolves through the registry, and hands bytes to a driver. Future-proofed for edge offload.

PublicDriver StreamDriver X-Accel-Redirect X-Sendfile S3 R2 CDN

Artifacts in transit: public/build/manifest.json · storage/app/assetshield/registry.json

Threat model

Audited by attack, not by claim.

Every input is treated as untrusted. The route accepts only opaque IDs; the registry is the only channel to a file; signatures are verified in constant time; and the honest limits are documented, not hidden.

  • Path traversal → structurally impossible
  • .env · PHP · vendor → never deliverable
  • Forged / expired signature → 403, constant-time
  • Secrets → never in HTML, JS, logs, or errors
  • Source maps → never shipped for protected assets

Artisan

Diagnostics that tell the truth

Four commands keep a deploy honest — from first publish to pre-flight health check.

01
asset-shield:install

Publishes config, creates the registry path, prints the Vite wiring. Never overwrites your files without asking.

02
asset-shield:build

Verifies Vite and the manifest, then regenerates and validates the registry. Build errors are loud, never silent.

03
asset-shield:status

Snapshots the configuration — mode, manifest, registry, signatures, obfuscation, source maps.

04
asset-shield:doctor

Inspects APP_ENV, debug flags, manifest, maps, node_modules, .env placement, Debugbar, and registry validity. Actionable warnings.

Install & docs

Ship a build. Protect it. In four lines.

quickstart
$ composer require shamimstack/asset-shield
$ npm i -D @asset-shield/vite-plugin
$ php artisan asset-shield:install
 
// vite.config.js
import { assetShieldVite } from '@asset-shield/vite-plugin';
plugins: [ laravel({ input: […], refresh: true }), assetShieldVite() ]
 
$ npm run build && php artisan asset-shield:build
✔ protected build ready
